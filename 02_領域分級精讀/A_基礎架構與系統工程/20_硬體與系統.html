G1｜3 分鐘速覽

一句話說明

這個領域處理的是怎麼在物理矽晶片的熱力學極限內，搬運和排程千億參數的數學圖。峰值算力每兩年成長 3.0\times，DRAM 與跨卡互連頻寬卻只成長 1.6\times／1.4\times。為了應付這道 AI 記憶體牆（Memory Wall），本領域用的工具有 Roofline 算術強度法則、算子內／算子間雙層自動並行編譯、作業系統虛擬分頁式的 KV 管理（PagedAttention），以及基數樹前綴共享（RadixAttention）。

  • 這個領域要解決什麼問題？ 外行人以為大模型的瓶頸是晶片算得不夠快。系統架構師知道實際情況是，現代 GPU 絕大部分時間都在等資料從記憶體或網路線搬過來。這道 AI 記憶體牆（Gholami et al., 2024）在訓練與推論兩端各有一組矛盾：
    1. 訓練端的顯存爆炸與通訊塞車矛盾：百億至兆級的參數，連同梯度與 Adam 優化器動量，遠超過單張 GPU 的容量。切得太碎（張量並行跨出單機 NVLink），會被跨機網路延遲拖垮。切得太粗（純管線並行），又會產生大量設備空轉等待的管線氣泡（Pipeline Bubbles）。
    2. 推論端的頻寬飢餓與動態顯存碎片矛盾：自迴歸解碼每輸出 1 個 Token，就得把數百 GB 的權重和隨長度動態膨脹的 KV Cache 從高頻寬記憶體（HBM）重新搬進計算核心一次，算術強度低到趨近 1 FLOP/Byte。更糟的是，傳統系統無法預知模型會回答多長，只能為每個請求預先圈出最大長度的連續顯存。結果 60% 到 80% 的昂貴顯存變成無法利用的碎片，批次並行的吞吐量因此上不去。
  • 直覺模型（不用公式也能懂的比喻）： 把大型 AI 系統想像成米其林中央廚房的走廊，加上智慧連鎖餐廳的座位調度：
    • Roofline 模型與記憶體牆（Williams et al., 2009; Gholami et al., 2024）：主廚揮刀的速度已經超過音速（Tensor Core 峰值 FLOPS），但從冷凍庫通往料理台的走廊窄得只能單人通過（記憶體頻寬牆）。如果每跑一趟冷凍庫只拿一顆蒜頭回來切一刀（單批次逐 Token 解碼），主廚 98% 的時間都在乾等。要讓他的刀不閒著，得把幾十張訂單湊成一籃一次搬進來切（大 Batch 推論），或讓小助手先猜好接下來五道菜一併端上來，讓主廚一次驗收（推測解碼 Speculative Decoding）。
    • PagedAttention（vLLM）與 RadixAttention（SGLang）：傳統的顯存管理像老派宴會廳。客人一進門，不知道他會帶幾個朋友，就先封鎖一整張 20 人長桌，最後只坐 3 人，門外卻大排長龍。PagedAttention 引入作業系統的虛擬記憶體分頁，把全場拆成 4 人小方桌，隨到隨拼，不浪費空位。SGLang 的 RadixAttention 更進一步，把所有客人都會點的固定高湯鍋底（系統提示詞、Few-shot 範例、多輪對話與樹搜尋的共享前綴）存在基數樹（Radix Tree）快取裡，跨請求直接共用，不必重熬。
    • Megatron-LM 與 Alpa 自動並行：要造一艘單一船塢塞不下的巨輪時，Megatron-LM 把矩陣直切配橫切，讓工人做完兩道工序才對一次帳（每層只需一次 All-Reduce）。Alpa 則像全自動的總工程師，用雙層最佳化（整數線性規劃＋動態規劃）自動算出哪裡該多人合焊一塊鋼板（算子內並行）、哪裡該分段做流水線組裝（算子間並行）。
  • 其他領域的研究者為什麼要關心它？它和哪些領域相接？ 本領域收錄 97 篇文獻，決定各種理論架構能不能變成實際可用的系統。它解釋了 01_Transformer核心 為什麼從標準 MHA 全面轉向 GQA / MLA（都是為了壓縮 KV Cache 的頻寬需求），也解釋了 02_非Transformer架構（Mamba / 線性注意力 / CfC）在超長上下文推論上的硬體優勢。SGLang 的結構化有限狀態機解碼與樹狀快取，直接提升 10_工具鏈 自主代理與 05_形式化與推理 測試時樹搜尋的執行效率。2026 年最新的 vLLM Hook 則在高吞吐引擎內部開放可程式化掛鉤，讓 06_學習動力學與可解釋性 的激活引導與 19_AI安全攻防 的線上護欄可以直接部署上線。

主要概念（白話說法對照嚴格定義）

  1. Roofline 效能物理上界與 AI 記憶體牆（Arithmetic Intensity, Memory Wall & CIM Roofline）

    • 直覺理解：這裡的問題是，任何程式跑在任何晶片（GPU、Arm CPU 或存算一體晶片）上，最快能跑多快。柏克萊團隊（Williams, Waterman & Patterson, 2009）用一張雙對數折線圖回答，就是 Roofline 模型。橫軸是每從記憶體搬 1 Byte 資料能做幾次浮點運算（算術強度 Arithmetic Intensity I），縱軸是實測的每秒浮點運算數（FLOPS）。斜坡屋簷由記憶體頻寬決定，平頂屋頂由晶片峰值算力決定。Gholami et al.（2024）在 AI and Memory Wall 中算過：過去 20 年，伺服器峰值算力每兩年成長 3.0\times，DRAM 頻寬每兩年只成長 1.6\times，互連頻寬只有 1.4\times。結果屋頂越來越高，斜坡卻越來越緩。LLM 預填充（Prefill，矩陣乘矩陣，I 高）還碰得到平頂的算力上限，自迴歸解碼（Decode，矩陣乘向量，I \approx 1\sim 2）則卡在左側斜坡的底端，買再貴的算力也快不起來。
    • 機制或核心表達式：給定硬體峰值算力 P_{\text{peak}}（FLOP/s）與峰值記憶體頻寬 B_{\text{peak}}（Byte/s），算子的算術強度 I = W_{\text{FLOPs}} / Q_{\text{Bytes}} 決定可達效能的硬上界：
      P_{\text{attainable}}(I) = \min\!\Big( P_{\text{peak}}, \; I \times B_{\text{peak}} \Big), \qquad \text{脊點（Ridge Point） } I^* = \frac{P_{\text{peak}}}{B_{\text{peak}}}
      當 I < I^* 時，系統處於記憶體受限區（Memory-Bound）。這時要提速只有兩條路：壓縮資料搬運量 Q_{\text{Bytes}}（權重／KV 量化、算子融合以減少中間寫回），或拉高 I（增大 Batch、推測解碼）。2026 年的工作把這套分析框架延伸到邊緣 Arm CPU 的混合量化與核心協同最佳化（Zhou, 2026），以及存算一體架構的適配評估（CIM-Aware Roofline, Ma et al., 2026）。
    • 能做到什麼，代價是什麼：在動手寫任何一行 CUDA / Neon 組合語言之前，就能很快判定瓶頸在算力還是頻寬，並算出理論加速比的上限。代價是經典的一階 Roofline 假設資料預取與計算完全重疊。要處理細粒度的快取階層（SRAM、HBM、PCIe）與跨卡網路的尾延遲，得擴展成多階層、通訊感知的 Roofline。

  2. 多維分散式並行與雙層自動編譯最佳化（Megatron-LM, Alpa, DeepSpeed & SpotServe）

    • 直覺理解：一個單卡放不下的巨型神經網路，要拆給上千張 GPU 協同訓練與推論。Megatron-LM（Shoeybi et al., 2019）提出層內張量並行（Tensor Parallelism）：把雙層 MLP 的第一個權重矩陣直著切（Column Parallel），直接過非線性激活，第二個權重矩陣橫著切（Row Parallel），中間完全不需要跨卡通訊，整層算完才做唯一一次 All-Reduce。但遇到異質模型（如 MoE、長序列或圖卷積網路 Scardapane et al., 2021）與複雜的叢集拓撲，手工排並行計畫非常困難。Alpa（Zheng et al., 2022）把這件事自動化。它的觀察是：資料並行與張量並行屬於算子內（Intra-operator，需要高頻寬 NVLink），管線並行屬於算子間（Inter-operator，只傳邊界激活，適合慢速的跨機網路）。於是它用兩層階層式最佳化，自動產生接近、甚至超越人類專家調優的執行計畫。
    • 機制或核心表達式：Megatron-LM 的層內切分利用分塊矩陣恆等式消除中間同步：
      Y = \mathrm{GeLU}(X [A_1, A_2]) \begin{bmatrix} B_1 \\ B_2 \end{bmatrix} = \mathrm{GeLU}(X A_1) B_1 + \mathrm{GeLU}(X A_2) B_2 \xrightarrow{\text{All-Reduce}} Y
      Alpa 則把裝置叢集切成子網格（Device Mesh）。內層針對單一管線階段，用整數線性規劃（ILP）極小化算子內計算與集合通訊的成本。外層用動態規劃（DP）切分計算圖的階段，並最小化最慢階段的耗時與管線氣泡延遲。推論與雲端彈性方面，DeepSpeed Inference（Aminabadi et al., 2022）結合深度核融合與多 GPU 張量切分，降低百億參數模型與 MoE 的延遲。SpotServe（Miao et al., 2024, ASPLOS）則利用動態重並行與低開銷的狀態遷移，讓大模型能穩定跑在搶佔式實例（Spot Instances）上。這類實例隨時可能被雲端回收，但價格便宜數倍。
    • 能做到什麼，代價是什麼：支撐兆級參數的穩定擴展（可參照 Li et al., 2024 對分散式集合通訊流量的細緻特徵化，與 Zeng et al., 2023 的分散式 LLM 訓練體系），並大幅降低雲端推理的費用。代價是張量並行非常依賴機內的超高速互連（NVLink）。一旦跨節點硬開張量並行，每次前向反向都有數百次 All-Reduce 同步屏障，吞吐效率會被吃光。

  3. 作業系統級 KV 記憶體虛擬化、結構化前綴快取與三級卸載（PagedAttention, SGLang & FlexGen）

    • 直覺理解：2023 年之前，LLM 推論系統為每個請求預留一大塊連續顯存來放 KV Cache，就像早期沒有分頁機制的電腦，既浪費空間，又無法跨請求共享。vLLM / PagedAttention（Kwon et al., 2023, SOSP）把作業系統教科書裡的虛擬記憶體分頁（Virtual Memory Paging）搬進自注意力核心：邏輯上連續的 Token KV 向量，在實體 HBM 中被打散，存進固定大小的非連續區塊（Blocks），再透過一張輕量的區塊映射表（Block Table）即時查找。顯存浪費因此壓到 4% 以下，吞吐量提高 2–4 倍。接著 SGLang（Zheng et al., 2023, NeurIPS）發現，現代 Agent、思維樹（Tree-of-Thought）與結構化 JSON 輸出有大量跨呼叫的重複前綴，於是提出 RadixAttention：請求結束後不急著丟棄 KV 分頁，而是掛在以 LRU 淘汰管理的基數樹（Radix Tree）上，後續任何共享前綴的請求都可以直接複用，不必重算。它還搭配壓縮有限狀態機（Compressed FSM），一次跳過確定性的語法符號。手邊只有一張顯存不足的單卡時，FlexGen（Sheng et al., 2023）用線性規劃調度 GPU–CPU–NVMe 固態硬碟三級儲存的 Z 字形區塊遍歷（Zig-zag Schedule），做到離線批次的高吞吐推論。
    • 機制或核心表達式：在 PagedAttention 中，設實體 KV 區塊大小為 B 個 Token，第 j 個邏輯區塊映射到實體位址 p(j)。自注意力的分塊計算改寫成對非連續實體分頁的聚合讀取，不再需要重新分配連續記憶體：
      \mathrm{Attention}(q_i, K_{\le i}, V_{\le i}) = \sum_{j=1}^{\lceil i/B \rceil} \mathrm{SoftmaxBlock}\!\left(\frac{q_i K_{\text{phys}[p(j)]}^\top}{\sqrt{d}}\right) V_{\text{phys}[p(j)]}
      這個設計也直接支援平行採樣與 Beam Search 的寫入時複製（Copy-on-Write）：多個候選分支共享同一個實體前綴區塊，只在分叉寫入新 Token 時才複製單一尾端頁。
    • 能做到什麼，代價是什麼：線上高並發服務的批次上限與多輪 Agent 複雜控制流的執行效率因此大幅提高，這套設計也成為當代開源推論引擎的工業標準。代價是非連續區塊的間接尋址需要專門改寫底層的 GPU Attention Kernel，才能維持記憶體合併存取（Coalesced Access）的效率。

  4. 長上下文分塊預填充壓縮、省顯存推測解碼與引擎內部可程式化（CompactAttention, TideKV, Speculative Decoding & vLLM Hook）

    • 直覺理解：到了 2026 年，長達數十萬字的超長上下文與測試時安全干預，給推論系統帶來三個新問題。(1) 為了不讓一個十萬字的長提示詞卡住其他所有短請求，現代引擎普遍採用分塊預填充（Chunked Prefill），把長提示切成小塊分批算。但現有的稀疏注意力在短查詢塊下效率大跌，CompactAttention（Song et al., 2026）因此提出區塊聯集 KV 選擇（Block-Union KV Selection），重新取得硬體加速。(2) 全量預填充後再壓縮 KV，仍會撞上預填充期間的顯存峰值。太早按塊淘汰，又會因為還沒看完後文而誤刪關鍵資訊。TideKV（Wang et al., 2026）用逐層延遲 KV 淘汰（Layer-Wise Delayed Eviction）同時顧到低顯存峰值與全局語意保真。(3) 在消費級單卡上跑推測解碼，同時載入草稿模型與目標模型容易爆顯存，Patel（2026）設計了記憶體高效的推測解碼來解決容量限制。另外，最能連接其他領域的是 vLLM Hook v0（Ko & Chen, 2026）：生產級 vLLM 原本高度封裝、像個黑盒，它用輕量外掛開放了已部署模型內部各層激活狀態的可程式化讀寫介面。
    • 機制或核心表達式：在分塊預填充序列 X = [C_1, C_2, \dots, C_M] 中，TideKV 錯開層間與塊間的生命週期，壓平峰值顯存 \max_{t, \ell} M_{\text{KV}}(t, \ell)，避免在還沒看完完整上下文之前就永久丟棄底層鍵值。vLLM Hook 則在編譯排程迴圈的第 \ell 層插入可組合的算子掛鉤 \tilde{\mathbf{h}}^{(\ell)} = \mathcal{G}_\phi\!\left(\mathbf{h}^{(\ell)};\, \text{context}\right)，讓測試時激活引導（Activation Steering）、探針監測與動態對齊可以在 PagedAttention 的批次執行中原生運行。
    • 能做到什麼，代價是什麼：百萬級長文本推論、消費級單卡加速與線上白盒安全干預，因此能從實驗室裡跑得很慢的 PyTorch 腳本，進到高吞吐的生產叢集。代價是動態淘汰與運行時掛鉤如果設計不當，可能破壞 CUDA Graph 的靜態捕獲優化，需要在可程式化的靈活度與微秒級排程開銷之間仔細權衡。

G3｜開放問題與跨域遷移

學界目前的爭論與未解問題

  1. 靜態圖封裝加速，與測試時動態稀疏及內部白盒干預之間的架構拉鋸：為了餵飽高速 Tensor Core 並掩蓋 Python 排程延遲，生產引擎傾向把計算圖、記憶體池與固定分頁格式全部靜態化（CUDA Graphs / Mega-Kernels）。但演算法這邊的新做法，不論是依內容動態剪除 KV 的長文本壓縮（CompactAttention / TideKV）、動態專家路由（MoE），還是安全與可解釋性需要的逐 Token 內部激活讀寫（vLLM Hook），都是高度動態、條件分支密集的操作。怎麼設計新一代的 AI 虛擬機抽象，既支援細粒度的運行時自省與稀疏跳躍，又不打斷硬體流水線的滿載運作，是系統與演算法協同設計的主要課題。
  2. 逼近馮・紐曼搬運瓶頸的極限，與存算一體（CIM）及邊緣異質硬體在精度與彈性之間的取捨：AI and Memory Wall（Gholami et al., 2024）顯示，只要權重與 KV 還得在獨立的記憶體與運算核心之間往返搬運，能耗與頻寬牆終究會限制擴展上限。存算一體（Compute-in-Memory, Ma et al., 2026）直接在記憶體陣列內完成乘加運算，能效有望有數量級的提升（呼應 28_非平衡態統計力學與隨機熱力學 的計算熱力學能耗下界）。但自迴歸推論每秒都在動態生成並寫入新的 KV Cache，硬體又有混合精度與非理想雜訊，CIM 要怎麼從靜態權重加速走到全動態注意力加速，還沒有答案。

可以借到其他領域的結構

  • 把古典作業系統五十年的設計模式對應到大模型系統：近三年影響最大的幾項 AI 系統進展都找得到對應。PagedAttention 對應虛擬記憶體分頁與 fork() 寫入時複製。SGLang RadixAttention 對應檔案系統的樹狀緩衝快取（Buffer Cache）。FlexGen 對應外部排序與虛擬交換區的 I/O 排程。vLLM Hook 則像 Linux 核心的 eBPF 動態追蹤掛鉤，不重編譯核心、不停機，就能安全注入自訂的監測與過濾邏輯。在古典 OS、資料庫（MVCC 交易隔離）與網路路由器中成熟運作的機制，幾乎都可能是下一個 SOSP / OSDI 等級的 AI 系統題目。
  • 用算術強度脊點 I^* 重新檢視科學計算與機器學習演算法：跨領域研究者常只數算術乘法次數（FLOPs），不數記憶體讀寫的位元組（Bytes）。設計 02_非Transformer架構 的新型遞迴算子、03_數學結構化ML 的圖與層論捲積，或 27_算子學習與PDE基礎模型 的多尺度網格求解器時，應該先用 Roofline 檢驗算術強度。用區塊化重排（Tiling）與算子融合，把中間狀態留在片上的高速 SRAM 內算完再寫回，實際加速往往比在數學上砍掉一半乘法次數還大。
