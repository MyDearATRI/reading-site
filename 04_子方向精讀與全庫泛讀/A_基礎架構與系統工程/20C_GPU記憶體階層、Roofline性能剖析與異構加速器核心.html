G1｜3 分鐘泛讀速覽

核心定位

本子方向位於 硬體與系統 的底層架構與核心執行基礎，向下直面單顆加速器內部的暫存器、SRAM、HBM 與跨節點／主機記憶體階層限制，向上決定 大模型推論服務、PagedAttention與預填充解碼分離 與 大規模分散式並行訓練、管線排程與集合通訊 的真實算力利用率。演進主線從提出運算與頻寬雙上界的 Roofline 視覺性能模型（Williams 等人，2009），推進至以線性規劃協調 GPU/CPU/磁碟卸載與低位元壓縮的單卡大模型引擎（FlexGen、DeepSpeed Inference），再發展到貼合 GPU 硬體階層的三層簡潔核心抽象（ThunderKittens）以及資源受限裝置上的協同推測解碼與混合架構 Roofline 剖析。

  • 核心問題：AI 模型運算規模與現代加速器的物理階層之間存在雙重落差。第一，高階運算核心的浮點吞吐遠高於 HBM、PCIe 主機記憶體與磁碟頻寬，許多張量運算或客製 GPU 核心即使算力需求不大，實測性能卻長期卡在資料搬運上限（Williams 等人，2009；Röhrig-Zöllner 等人，2021），且手工撰寫能協調 warp 矩陣指令、非同步記憶體載入與區塊排程的高效核心極難維護（Spector 等人，2024）。第二，在單張 16 GB 消費級或邊緣 GPU 上部署數百億參數模型或雙模型推測解碼時，顯存容量不足以容納完整權重與快取，而天真的主機交換（swapping）會因頻寬過低導致推論延遲失效（Sheng 等人，2023；Niu 等人，2024；Patel，2026）。
  • 直覺模型：可以把 GPU 記憶體階層比喻成一間分工嚴格的餐廳廚房：計算單元是切菜飛快的主廚，on-chip 共享記憶體是隨手可拿的工作檯，HBM 顯存是廚房內的冷藏櫃，而 CPU 主記憶體與 SSD 則是門外的儲藏室與遠端倉庫。Roofline 模型就像一張標出「主廚刀速上限」與「取料走廊寬度上限」的產能上限圖：只要一道菜每取一次食材只切一兩刀（低算術強度），出菜速度就永遠卡在走廊走路時間，再快的刀法也沒用；ThunderKittens 則是把工作檯規格統一成 16x16 標準餐盤並讓助手在切菜時提前非同步去冷藏櫃備料，而 FlexGen 則透過數學規劃算出食材該堆在冷藏櫃還是門外倉庫才不至於來回空跑。
  • 分階段閱讀路線：第一步先讀 Williams 等人 (2009)（Roofline 模型）與 Röhrig-Zöllner 等人 (2021)（高階 SVD 的 Roofline 分析），建立算術強度與記憶體頻寬受限（memory-bound）及計算受限（compute-bound）的基礎判別工具。第二步精讀 Aminabadi 等人 (2022)（DeepSpeed Inference）、Sheng 等人 (2023)（FlexGen）與 Spector 等人 (2024)（ThunderKittens），掌握多卡與異構儲存卸載的系統解法、線性規劃張量配置以及對應 warp/block/grid 三層階層的 GPU 核心寫法。第三步閱讀 Niu 等人 (2024)（RTiL）與 Patel (2026) 關於記憶體受限消費級 GPU 上的推測解碼與量化實證，並可延伸參考 Zhou (2026) 與 Ma 等人 (2026) 將 Roofline 框架擴展至 Arm CPU 與記憶體內運算（CIM）架構的最新題目。

核心機制與推導要點

  1. Roofline 性能模型與算術強度脊點 (Roofline Performance Model and Operational Intensity)

    • 直覺理解：每個程式在特定硬體上的理論最快速度只受兩個天花板夾擊：不是算力峰值（算太慢），就是記憶體頻寬乘以每搬運一位元組能做的運算次數（搬太慢）；看懂這個拐點就能決定該最佳化演算法重用率還是壓低搬運量。
    • 機制或核心表達式：Williams 等人 (2009) 提出以雙對數座標呈現的 Roofline 模型：設硬體峰值浮點運算率為 P_{\mathrm{peak}}（FLOP/s），主記憶體頻寬為 B_{\mathrm{mem}}（Byte/s），程式的算術強度（operational intensity）定義為每存取一位元組記憶體所執行的浮點運算數 I = \frac{\text{FLOPs}}{\text{Bytes}}。則實際可達性能 P 受限於 P \le \min(P_{\mathrm{peak}}, B_{\mathrm{mem}} \cdot I)，兩條線段交會於硬體脊點 I^* = P_{\mathrm{peak}} / B_{\mathrm{mem}}。在矩陣與張量分解實務中，Röhrig-Zöllner 等人 (2021) 利用簡易 Roofline 模型證明，當目標張量秩（rank）夠小時，張量列車奇異值分解（TT-SVD）的性能受限於資料搬移，在合理假設下的理論最小執行時間約為讀取全部資料兩次的耗時，並據此實作接近最佳下界的分散式秩保留 TSQR 步驟。
    • 能做到什麼，代價是什麼：Roofline 以極少硬體參數提供直觀且可跨多核、GPU、CPU 與異質架構比較的性能上限診斷；代價是基礎版本假設完全重疊與連續串流存取，實務上還需疊加網路互連、快取未命中或運算元啟動延遲等次級天花板才足以指導細部核心調校。

  2. GPU/CPU/磁碟異構記憶體卸載與線性規劃排程 (Heterogeneous Memory Offloading and LP Scheduling)

    • 直覺理解：當模型大到單張 GPU 裝不下時，不一定要硬買多張伺服器卡；只要把不同層的權重、激活與 KV 快取按運算順序有規劃地放在 GPU、主機記憶體與硬碟之間輪轉並做低位元壓縮，就能用單卡跑出高吞吐批次推論。
    • 機制或核心表達式：針對延遲較不敏感但追求高批次吞吐的離線／批次生成場景，FlexGen（Sheng 等人，2023）聚合 GPU 顯存、CPU 主記憶體與磁碟三層資源，將「張量在各層級的儲存位置與存取排程型樣」形式化為線性規劃（LP）問題進行自動搜尋，並進一步將模型權重與注意力快取壓縮至 4 位元（4-bit）以放大可行批次空間，成功在單張 16 GB GPU 上執行 OPT-175B 並取得高吞吐表現。對於多卡或稀疏 MoE 架構，DeepSpeed Inference（Aminabadi 等人，2022）則協同配置不同記憶體與儲存層級以同時因應低延遲或高吞吐目標。
    • 能做到什麼，代價是什麼：透過線性規劃與 4 位元量化突破單卡顯存容量限制，在有限硬體大幅提升批次總吞吐；代價是跨 PCIe 與磁碟搬移權重會大幅拉高單一請求的端到端延遲，因此主要適用於延遲不敏感的批次處理而非即時互動服務。

  3. 三層級 GPU 核心抽象：Warp 磚塊、區塊重疊與網格排程 (ThunderKittens Three-Level Kernel Abstractions)

    • 直覺理解：手寫高效能 CUDA 核心之所以困難，往往不是數學複雜，而是要同時對齊硬體張量核心尺寸與多層非同步排程；透過把核心程式統一成標準 16x16 小矩陣磚塊搭配預製的跨 warp 重疊樣板，就能用接近 PyTorch 的直覺寫出逼近理論峰值的底層核心。
    • 機制或核心表達式：針對 AI 架構映射至 GPU 硬體與線形注意力等算子實測低於理論上限的問題，ThunderKittens（Spector 等人，2024）將設計抽象直接對齊 GPU 硬體三層結構：(1) 在 warp 層級，定義 16 \times 16 矩陣磚塊（matrix tiles）為基本資料結構，並提供類 PyTorch 語法的平行磚塊運算原語；(2) 在執行緒塊（thread-block）層級，提供跨平行 warps 重疊執行非同步操作（如載入與計算重疊）的標準樣板；(3) 在網格（grid）層級，提供輔助機制以隱藏區塊啟動、拆卸（tear-down）與記憶體存取延遲。
    • 能做到什麼，代價是什麼：大幅降低開發與維護高速 AI 核心的工程門檻，同時逼近手寫最佳化核心的硬體上限；代價是核心資料流需能貼合固定大小的 16x16 磚塊幾何，對極度不規則稀疏存取或單向標量邏輯的適用性較弱。

  4. 記憶體受限裝置的量化推測解碼與 CPU–GPU 協同驗證 (Memory-Efficient Speculative and Collaborative Inference)

    • 直覺理解：在 16 GB 筆電或工作站顯卡上同時載入大目標模型與小草稿模型往往會直接爆顯存；透過把草稿與驗證任務分攤到 CPU 或結合模型量化與記憶體管理，既能享受到推測解碼的平行驗證加速，又不會把顯存塞滿。
    • 機制或核心表達式：為解決本地記憶體受限裝置進行主機交換過慢的問題，RTiL（Niu 等人，2024）採用協同推論架構：由輕量級 LLM 生成候選詞元再交給較強大的目標模型驗證品質，並將部分推論負載分派至 CPU 與最佳化資料搬運路徑，在不損失輸出品質下顯著縮短推論時間。進一步針對消費級 GPU 上的標準推測解碼（需同時常駐草稿與目標模型），Patel (2026) 整合模型量化與記憶體管理策略，使 LLaMA-7B 的推測解碼在 16 GB NVIDIA RTX A4000 上僅消耗 12.0 GB 顯存，取得 76.3% 平均接受率、2.31 倍詞元生成吞吐加速與 56.8% 延遲降低。
    • 能做到什麼，代價是什麼：讓推測解碼與協同驗證能在 16 GB 級消費或邊緣顯卡上實際落地，兼顧本地隱私與即時反應速度；代價是量子化誤差若壓低草稿與目標模型輸出分佈的一致性，接受率下降會直接削弱推測加速比。

主動學習自測題

  1. 利用 Roofline 模型診斷算子瓶頸與指導演算法設計：假設某張加速器的峰值算力為 P_{\mathrm{peak}} = 100 TFLOP/s，記憶體頻寬為 B_{\mathrm{mem}} = 2 TB/s。若某個張量運算核目前的算術強度只有 I = 10 FLOP/Byte，請問該算子的硬體脊點 I^* 與理論上限性能各是多少？此時單純將計算單元的時脈再提升一倍，實際速度會有變化嗎？
參考思路

硬體脊點為 I^* = P_{\mathrm{peak}} / B_{\mathrm{mem}} = 100 \times 10^{12} / (2 \times 10^{12}) = 50 FLOP/Byte。因為目前程式的算術強度 I = 10 < I^*，屬於記憶體頻寬受限區間，理論最大效能僅為 B_{\mathrm{mem}} \cdot I = 2 \times 10^{12} \times 10 = 20 TFLOP/s（僅達峰值算力兩成）。因此只提升算力峰值 P_{\mathrm{peak}} 對實際執行速度完全沒有幫助，必須透過核心融合（kernel fusion）、SRAM 分塊重用或低位元量化減少資料搬運量，把算術強度推向脊點右側。

  1. FlexGen 離線卸載策略與 RTiL 本地即時協同的場景分工：FlexGen（Sheng 等人，2023）與 RTiL（Niu 等人，2024）都處理「模型無法完整放入單卡 GPU 顯存」的問題，為何 FlexGen 適合靠線性規劃把權重卸載到磁碟，而 RTiL 卻必須避免傳統的慢速資料交換（swapping）並改用輕量模型協同與 CPU 分工？
參考思路

關鍵在於兩者的延遲目標與批次假設不同。FlexGen 針對延遲不敏感的批次生成工作負載，透過極大化批次大小讓每一次從 CPU 或磁碟搬入層權重的 I/O 成本能被數百上千個序列攤提，換取高總吞吐量。相反地，RTiL 面向本地裝置上的即時單請求推論，每次生成只有單一或極少請求，無法靠大批量攤平 PCIe/主記憶體來回交換的延遲，因此必須藉助輕量草稿生成、批次化驗證與 CPU 協同運算來縮減單請求端到端時間。

G3｜跨領域連結與開放問題

學界目前的爭論與未解問題

  1. 非 GPU 異質架構（Arm CPU 與 CIM）的統一 Roofline 剖析標準：隨著邊緣與新型硬體興起，Zhou (2026) 與 Ma 等人 (2026) 近期相繼將 Roofline 分析擴展至 Arm CPU 混合量化與記憶體內運算（Compute-in-Memory, CIM）評估。然而傳統僅包含單一 P_{\mathrm{peak}} 與 B_{\mathrm{mem}} 的雙段折線難以精確刻畫 CIM 陣列內類比／數位轉換開銷、混合精度指令吞吐切換與多級快取協同，建立能跨 GPU、CPU 與 CIM 公平預測實際延遲的擴展 Roofline 模型仍在發展中。
  2. 高階抽象核心框架對動態稀疏與極端低位元算子的覆蓋度：ThunderKittens（Spector 等人，2024）以 16 \times 16 矩陣磚塊與 warp 樣板成功簡化了稠密與線性注意力核心的撰寫，但當上層演算法走向非結構化權重剪枝、不規則分塊稀疏 KV 選擇或 4 位元以下混合反量化融合時，如何在不退回繁瑣手工 PTX／匯編的前提下讓磚塊級抽象直接產生高頻寬利用率的核心，仍是系統編譯與核心語言設計的開放挑戰。

跨領域結構遷移

  • Roofline 頻寬受限模型對推論服務分頁與快取選擇的指導：本子方向的算術強度分析與 16 \times 16 磚塊非同步重疊技術，可直接移植至 大模型推論服務、PagedAttention與預填充解碼分離 中執行分頁 KV 讀取與 GQA 群組區塊選擇（如 CompactAttention）的底層注意力核心，精確評估解碼批次與量化壓縮帶來的頻寬收益。
  • 單卡讀取下界思維向分散式集合通訊排程的遷移：Röhrig-Zöllner 等人 (2021) 從 Roofline 出發為 TT-SVD 推導「最少讀取資料兩次」的演算法下界並實作分散式平行 TSQR，這種先建立資料搬運理論下界再反推通訊壓縮演算法的方法論，可直接遷移至 大規模分散式並行訓練、管線排程與集合通訊 中的梯度歸約與跨節點激活檢查點設計。
  • 硬體友善狀態空間算子與連續時間模型的磚塊核心實作：ThunderKittens（Spector 等人，2024）明確指出線性注意力等非標準算子往往因難以映射至 GPU 記憶體階層而未達理論峰值；該套三層磚塊與非同步重疊抽象正適合用於加速 連續時間動力學、狀態空間與液態神經網路 中的線性遞迴掃描與狀態空間捲積核。

G4｜依學習順序排列的代表作精讀卡

1. Roofline: An Insightful Visual Performance Model for Floating-Point Programs and Multicore Architectures（2009）

  • 作者與出處：Samuel Williams, Andrew S. Waterman, David A. Patterson · Lawrence Berkeley National Laboratory
  • 核心問題：隨著多核處理器與加速器日益複雜，程式設計師與架構師缺乏一個既直觀又能同時結合計算峰值與記憶體頻寬限制的性能評估模型，難以判斷程式效能受限的真實來源。
  • 關鍵做法：提出 Roofline 視覺性能模型，以浮點運算對記憶體位元組比例（算術強度）為橫軸、可達浮點性能為縱軸，結合硬體峰值算力與記憶體頻寬上限描繪出直觀的效能天花板，協助開發者系統性判斷平行軟體應往增強資料局部性或改善平行計算推進。
  • 跨領域啟發：建立整個系統性能分析的通用坐標系，所有量化、核心融合與硬體設計皆可在此平面上檢驗是否逼近真實上界。
  • 連結：📚 Zotero 開啟 ｜ 官方連結

2. DeepSpeed Inference: Enabling Efficient Inference of Transformer Models at Unprecedented Scale（2022）

  • 作者與出處：Reza Yazdani Aminabadi, Samyam Rajbhandari, Minjia Zhang, Ammar Ahmad Awan, Cheng Li · International Conference for High Performance Computing, Networking, Storage and Analysis (SC)
  • 核心問題：Transformer 模型規模跨越千億參數且涵蓋混合專家（MoE）等稀疏變體，部署環境又橫跨單卡、多卡與多級異構記憶體儲存系統，同時須兼顧延遲關鍵或吞吐導向目標，導致通用高效推論系統極難設計。
  • 關鍵做法：提出 DeepSpeed Inference 全面性推論系統方案，整合針對稠密與稀疏 Transformer 的多卡低延遲／高吞吐執行機制，並協調跨不同記憶體與儲存層級的資源調度以支撐超大規模模型推論。
  • 跨領域啟發：銜接分散式大模型權重切分（大規模分散式並行訓練、管線排程與集合通訊）與異構儲存層級卸載架構的早期系統典範。

3. FlexGen: High-Throughput Generative Inference of Large Language Models with a Single GPU（2023）

  • 作者與出處：Ying Sheng, Lianmin Zheng, Binhang Yuan, Zhuohan Li, Max Ryabinin · arXiv (Cornell University)
  • 核心問題：大型語言模型極高的算力與顯存需求通常迫使部署者使用多張高階伺服器加速器，但在對延遲較不敏感的批次處理應用中，亟需探索如何在單張 16 GB 等級的有限 GPU 上完成超高吞吐推論。
  • 關鍵做法：提出 FlexGen 高吞吐生成引擎，聚合 GPU、CPU 與磁碟三層記憶體與計算資源，透過求解線性規劃（LP）問題搜尋最佳張量儲存與存取排程型樣，並將權重與注意力快取壓縮至 4 位元而幾乎不損準確率，在單張 16 GB GPU 上運行 OPT-175B 並取得相較既有卸載系統顯著更高的吞吐量。
  • 跨領域啟發：展示利用數學最佳化管理三級異構記憶體階層的威力，與 大模型推論服務、PagedAttention與預填充解碼分離 的低延遲線上服務形成鮮明取捨對比。

4. ThunderKittens: Simple, Fast, and Adorable AI Kernels（2024）

  • 作者與出處：Benjamin F. Spector, Simran Arora, Aaryan Singhal, Daniel Y. Fu, Christopher Ré · arXiv (Cornell University)
  • 核心問題：將新型 AI 架構映射至複雜 GPU 硬體已成領域瓶頸，即便在線性注意力等成熟算子上，手寫客製核心仍常無法達到理論性能門檻，且各代硬體特性歧異使核心極難撰寫與維護。
  • 關鍵做法：提出 ThunderKittens 核心開發框架，以精簡的三層抽象精確對應 GPU 階層：warp 層提供 16 \times 16 矩陣磚塊資料結構與類 PyTorch 平行磚塊運算、執行緒塊層提供跨平行 warps 重疊非同步操作的樣板、網格層提供隱藏啟動拆卸與記憶體成本的支援。
  • 跨領域啟發：為各類注意力變體與 連續時間動力學、狀態空間與液態神經網路 的狀態空間算子提供可維護的高性能底層核心範式。

5. RTiL: Real-Time Inference of Large Language Models on Memory-Constrained GPU Devices（2024）

  • 作者與出處：Juxin Niu, Wei Zhang, Chun Jason Xue, Nan Guan · IEEE International Conference on Embedded and Real-Time Computing Systems and Applications (RTCSA)
  • 核心問題：在本地機器部署大模型能提供即時反應、隱私保護與穩定性，但本地 GPU 顯存通常裝不下完整模型；若僅靠 GPU 與主記憶體間的慢速資料交換執行，推論延遲將高到難以實用。
  • 關鍵做法：提出系統化解決方案 RTiL，採取由輕量 LLM 生成輸出詞元並交由強大 LLM 驗證品質的協同推論架構，同時將部分推論負載分派至 CPU 並最佳化資料搬移，在維持與單獨使用大型模型相同輸出品質下顯著加速本地推論。
  • 跨領域啟發：將推測驗證思想與異構 CPU–GPU 負載切分結合，展示記憶體受限本地硬體上的即時推論系統設計。

6. Memory-Efficient Speculative Decoding for Large Language Model Inference on Commodity GPUs（2026）

  • 作者與出處：Tejas Patel · IEEE International Conference on Communication Systems and Network Technologies (CSNT)
  • 核心問題：推測解碼能靠小草稿模型平行預測並由目標模型驗證來加速生成，但傳統實作要求同時將草稿與目標模型載入記憶體，經常超出消費級 GPU 的有限顯存容量。
  • 關鍵做法：提出整合模型量化與最佳化記憶體管理的低顯存推測解碼框架，在配備 16 GB 顯存的 NVIDIA RTX A4000 上僅使用 12.0 GB 記憶體執行 LLaMA-7B 推論，保持輸出品質並達到 76.3% 平均接受率、2.31 倍詞元生成吞吐加速以及 56.8% 延遲縮減。
  • 跨領域啟發：實證證明量化壓縮與推測驗證在 16 GB 邊緣與消費級顯卡上的正交相乘效益。
